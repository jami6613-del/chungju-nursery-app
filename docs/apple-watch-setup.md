# 애플워치에서 파종 확인

워치 페이스의 **파종 확인** 버튼을 누르면 최신 요약을 불러옵니다.
한 결과창에 오늘의 파종과 내일 트레이 합계가 함께 표시됩니다. 내역이 많으면 스크롤합니다.
워치 페이스에 결과가 상시 표시되는 위젯은 아니며, 실행할 때마다 갱신됩니다.

## 적용 순서

1. 이 변경사항을 GitHub `main`에 병합하고, 연결된 Vercel 배포가 성공했는지 확인합니다.
2. 육묘장 앱에서 사용하는 **Supabase 프로젝트 → SQL Editor → New query**를 엽니다.
3. 저장소 루트의 `supabase-watch-sowing.sql` **전체**를 붙여넣고 **Run**을 한 번 누릅니다.
4. 육묘장 앱을 새로 열고 로그인합니다. 메인 화면 **오늘의 파종 아래 → ⌚ 워치 연결**을 누릅니다.
5. **조회키 발급** 후 **현재 파종 요약 확인**으로 앱 데이터와 대조합니다.

SQL은 새 조회키 테이블과 네 개의 함수를 추가합니다. 기존 주문·파종계획 데이터와 RLS는 변경하지 않습니다.
SQL 실패 시 트랜잭션 전체가 취소됩니다. 이미 성공한 SQL을 다시 실행해도 발급된 조회키를 삭제하지 않습니다.
프로젝트에는 기존 `sowing_plan_items`의 `tray_type`, `tray_custom`, `seed_owner` 컬럼과 `public.users.is_approved`가 있어야 합니다.

Vercel 서버 함수는 기존 환경변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 사용합니다.
해당 배포 환경(Production / Preview)에 두 값이 있어야 합니다. 추가 서비스 역할 키는 필요하지 않습니다.
직접 설정하는 대신 Supabase 연결을 제공하면 같은 SQL을 적용할 수 있습니다.

## 아이폰에서 단축어 만들기

1. **단축어 앱 → +**를 누르고 이름을 **파종 확인**으로 지정합니다.
2. **URL 콘텐츠 가져오기** 동작을 추가합니다. 워치 연결 창에서 **주소 복사** 후 URL 칸에 붙여넣습니다.
   - 운영 배포 주소: `https://chungju-nursery-app.vercel.app/api/watch-summary`
   - 이 주소는 위 변경사항을 운영 배포한 뒤 작동합니다.
3. 동작의 펼치기 화살표를 누르고 아래처럼 설정합니다.

| 항목 | 값 |
| --- | --- |
| 방법 | GET |
| 헤더 이름 | Authorization |
| 헤더 값 | 앱의 **헤더 값 복사**로 복사한 값 (`Bearer `와 조회키 포함) |

4. 아래에 **알림 보기** 동작을 추가합니다.
   - 제목: **파종 확인**
   - 메시지: 앞 동작의 **URL 콘텐츠 변수**를 선택합니다. ‘URL 콘텐츠’라는 글자를 직접 입력하지 않습니다.
   - **취소 버튼 보기**: 끄기
5. 아이폰에서 ▶를 눌러 한 번 실행하고, 육묘장 사이트 접근을 허용합니다.
6. 단축어 세부사항에서 **Apple Watch에서 보기**를 켭니다.

단축어 파일을 직접 만들어 가져오면 서명/공유 절차가 필요하므로, 위의 기본 동작 두 개를 아이폰에서 직접 구성하는 방법을 안내합니다.

## 워치에 한 번 누르는 버튼 배치

1. 워치 페이스를 길게 누릅니다.
2. **편집 → 컴플리케이션**으로 이동합니다.
3. 원하는 위치에서 **단축어 → 파종 확인**을 선택합니다. 단축어를 지원하는 위치/페이스를 사용합니다.
4. 페이스로 돌아가 버튼을 눌러 조회합니다. 최초 워치 실행 시에도 접근 허용이 필요할 수 있습니다.

최신 정보 조회에는 아이폰을 통한 연결, Wi-Fi 또는 셀룰러 연결이 필요합니다.
화면 크기와 글자 설정에 따라 줄바꿈·스크롤 정도가 달라집니다. 긴 내용은 크라운으로 아래까지 확인합니다.

## 예시 (실제 데이터가 아님)

```text
🌱 오늘 파종 9/14 · 1건

김농부 · 청상추
종자 주문자 · 200구
수량 100+10 (기본+추가)

📦 내일 트레이 9/15
128구 45개
200구 450개
406구 105개

조회 13:25 · 한국시간
```

## 데이터 기준과 연결 관리

- **오늘의 파종**과 **내일 화이트보드** 모두 `sowing_plan_items`를 사용합니다. `orders`를 섞어 중복 집계하지 않습니다.
- 한국 시간의 오늘·내일을 매 요청마다 DB에서 계산합니다. 따로 날짜를 입력할 필요가 없습니다.
- 내일 트레이별 합계는 기존 화이트보드 함수를 공유합니다. 직접입력 트레이도 포함합니다.
- 기존 합계는 기본/추가 각각 `parseInt`로 합산합니다. 예를 들어 `8+0.5`는 합계 8로 처리합니다. 이번 변경에서 이 업무 규칙은 변경하지 않았습니다. 오늘 수량에는 입력된 `8+0.5`가 그대로 표시됩니다.
- 조회키는 본인의 승인된 계정으로 발급하며, 1년 뒤 만료됩니다. **새로 발급**하면 이전 키는 즉시 해제되므로 단축어 헤더도 교체합니다.
- 원문 조회키는 발급 직후 창에서만 확인할 수 있습니다. 분실했다면 새로 발급합니다.
- **연결 해제**로 사용을 중단할 수 있습니다. 계정 승인이 취소되어도 조회가 차단됩니다.
- 단축어 공유 시 조회키도 전달됩니다. 다른 직원은 각자 로그인하여 본인 조회키를 발급합니다.

## 오류 해결

| 표시 | 조치 |
| --- | --- |
| 최초 설정 필요 | 올바른 Supabase 프로젝트에서 SQL 전체 실행 → 상태 다시 확인 |
| 요약 주소가 아직 배포되지 않음 / HTML이 표시됨 | Vercel에서 이 변경사항의 배포 완료 확인, 운영 주소 사용 |
| 조회키가 유효하지 않음 / 만료·해제 | 앱에서 새로 발급 → 단축어 Authorization 값 전체 교체 |
| 사이트 접근 요청 | 해당 육묘장 사이트에 대한 단축어 접근 허용 |
| 조회 시간 초과 / 네트워크 오류 | 워치 통신 연결 확인 후 다시 실행 |
| 파종계획 없음 | 해당 날짜의 화이트보드가 비어 있는 정상 결과 |

오류가 난 경우 오래된 자료나 ‘파종 없음’을 대신 표시하지 않습니다. 단축어 자체가 통신 오류로 중단되면 그 오류를 확인합니다.

## 개발 검증

`npm run test:watch`: 공유 합계·한글 텍스트·HTTP 인증/오류/캐시와 실제 PostgreSQL 엔진(PGlite)에서 조회키 수명·역할별 접근·반환 범위를 검사합니다. 운영 DB에는 접속하지 않습니다.
`npm run build`: 기존 Vite 앱 빌드. 로컬 `vite` 단독 실행에는 `/api` 함수 런타임이 없으므로 API 확인은 Vercel Preview에서 진행합니다.
